# Managing Memory

> Build a local knowledge base for progressive disclosure by the agent

<Callout type="info">
Memory and context retrieval belong to the **context machinery** layer of the harness (see [Harness Engineering](/en/docs/3-agent-harness/harness-engineering)). Progressive disclosure — the agent reads more only when a task needs it — is the same idea as Skills' on-demand loading: keep the baseline light, retrieve the depth lazily.
</Callout>

## Do You Need Memory?

**For most projects, Rules are sufficient.**

| Aspect | Rules | Memory |
|--------|-------|--------|
| **Determinism** | ✅ You know exactly which rules are applied | ⚠️ Agent reads on-demand, may miss some |
| **Use Cases** | Coding standards, tech stack conventions | Business knowledge, troubleshooting history |

Memory is suitable when:

- Extensive business domain knowledge needs AI understanding
- Need to track troubleshooting history
- Want AI to learn from past implementations

<Callout type="info">
Memory uses progressive disclosure — the agent reads based on needs. If certain rules must always apply, use [Always Apply Rules](/en/docs/3-agent-harness/how-rules-work#the-four-application-modes).
</Callout>

## Our Local Memory Practice

We chose **local files** over embedding solutions:

- **No tool call limits** - Cursor Agent can freely read local files
- **Cost-effective with powerful models** - with Opus-class models, more context in one request is economical
- **Version controlled** - memory evolves with your codebase

## Core Design: File System as Interaction Protocol

**Key insight**: Rules only need to tell the agent "what the `.memory` directory is". The detailed usage protocol lives in `.memory/README.md`.

Benefits:

- ✅ **Rules don't need dynamic maintenance** - Memory usage conventions evolve independently inside `.memory`
- ✅ **Self-documenting** - Agent gets the latest instructions by reading README.md
- ✅ **Decoupled** - The memory system expands without touching rules

### Rules Configuration (Minimal)

```markdown
---
alwaysApply: true
---

# Memory System

This project uses `.memory/` directory as knowledge base.

Before starting complex tasks, read `.memory/README.md` to understand usage.
```

### .memory/README.md (Full Protocol)

````markdown
# Project Memory Knowledge Base

This directory is the project memory, storing knowledge the AI Agent needs.

## 📖 Usage Protocol

### When to Read Memory
- Before starting complex tasks
- When dealing with business logic
- When uncertain about implementation details

### When to Update Memory
- After completing important features
- After solving tricky problems
- When documentation doesn't match reality

### Navigation
- Start from `index.md` for navigation
- Use `[[filename]]` links to jump
- Keep memory concise, avoid redundancy
````

## Progressive Disclosure

The agent reads memory incrementally based on task needs:

## Best Practices

| Do | Don't |
|----|-------|
| ✅ Keep each file under 200 lines | ❌ Duplicate content already in Rules |
| ✅ Use clear headers and bullet points | ❌ Store sensitive information |
| ✅ Update memory after important work | ❌ Let files grow too large |
