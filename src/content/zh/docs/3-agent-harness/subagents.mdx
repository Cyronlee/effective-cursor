# Subagents

> 独立 context 的子任务代理

## 定位

Subagents 是**独立 agent**：拥有自己的 context（上下文窗口），可配置独立的 prompt、工具与模型，在后台并行处理父任务的**离散部分**。它们是 harness **orchestration 层**的核心能力——让主对话保持聚焦，把子任务交给专精的代理。

## 内置 Subagents

Cursor 内置三种开箱即用的 subagents：

| 名称 | 用途 |
|------|------|
| **explore** | 代码库搜索：查找符号、文件、调用关系 |
| **bash** | shell 执行：跑命令、脚本、工具 |
| **browser** | 浏览器操作：通过 MCP 浏览器访问页面、验证 UI |

## 自定义 Subagents

在 `.cursor/agents/*.md` 中定义自己的 subagent：

<FileTree>
  <FileTree.Folder name=".cursor" defaultOpen>
    <FileTree.Folder name="agents" defaultOpen>
      <FileTree.File name="code-reviewer.md" />
      <FileTree.File name="test-writer.md" />
    </FileTree.Folder>
  </FileTree.Folder>
</FileTree>

````markdown
---
name: code-reviewer
description: 审查代码变更，检查正确性、风格与测试覆盖。当任务涉及 review 或 PR 检查时使用。
tools:
  - read_file
  - grep_search
  - list_dir
model: claude-4.5-opus
---

作为资深代码审查者，关注：
- 逻辑正确性与边界情况
- 与项目规范的一致性（参照 AGENTS.md）
- 测试覆盖是否充分
审查结束后输出结构化报告。
````

<Callout type="info">
**description 决定委派时机**：主 agent 会根据 subagent 的 description 判断「这个子任务要不要委派、委派给谁」。写清楚适用场景，委派才会准确。
</Callout>

## 编排模式

### 并行委派多个任务

把互不依赖的任务同时委派给多个 subagents（例如一个搜代码、一个跑测试、一个查文档），整体执行更快。

### 主对话 context 聚焦

子任务在 subagent 自己的 context 里完成，主对话不受其中间过程干扰——只接收结果。这让主对话能承接更大的任务而不被噪声撑爆上下文。

### 子任务专业化

不同 subagent 可配不同的 prompt、工具和模型：性能敏感的推理用强模型，机械任务用轻模型，避免「杀鸡用牛刀」。

<ChatExample>
{`帮我调查 @src/clients/user 的调用链，然后用 @.cursor/agents/code-reviewer 审查我刚写的 @src/features/dashboard 改动`}
</ChatExample>

## 成本与边界

| 情况 | 说明 |
|------|------|
| **简单任务** | 隔离成本可能更慢——委派开销有时超过直接在主对话完成 |
| **Cloud subagents** | 使用团队配置的 MCP，而非本地会话 MCP |
| **与 Skills 的区别** | Subagents 是「人」，Skills 是「知识/流程」（见下表） |

### Subagents vs Skills

| 维度 | Subagents | Skills |
|------|-----------|--------|
| 本质 | 独立 agent（有自己的 context 和工具） | 可复用工作流 / 知识包（SKILL.md） |
| 执行者 | 主 agent 委派，后台并行 | 当前 agent 按需加载并执行 |
| context | 独立 context，不占主对话 | 渐进式披露：启动只加载 name/description |
| 适用 | 离散子任务、并行探索、专业化审查 | 流程类任务：review、release、迁移 |

## Cloud 一句话

Cloud Agents 环境支持 `/in-cloud`（进云端 VM 执行）与 `/babysit`（远程盯 PR）——长任务与 PR 验证可以在隔离 VM 中运行、验证后再交付。配合 [验证闭环](/zh/docs/3-agent-harness/verify-closed-loop) 使用。
